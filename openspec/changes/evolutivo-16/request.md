# Evolutivo 16 — Guided help assistant ("Ayuda")

> Branch: `evolutivo-16`. Delivery: PR to master, merge after CI green, deploy (follow-up to evolutivo-15). Release 1.22.0.

## Request (summary of the user's words)
- Analyse the whole app (every section, screen, form, button, tab and flow: edits, deletes, filters, special states, unpaid rent, due dates, reversals, undo, documents, sub-accounts, transfers, alerts, logs, settings, profile, login and password reset) and turn every situation a low-tech user may need to solve into a static decision tree navigated by numbers, from general to specific. Final steps must be friendly and use the exact UI labels, say which screen/button/field to use, what happens on save and what to do if something does not add up.
- No AI and no API calls to answer: 100% hardcoded tree. Always offer "go back one step" and "main menu"; invalid input gets a kind reminder of the available numbers.
- A new "Ayuda" item in the main menu opens (does not navigate) a floating, WhatsApp-like chat window: bot bubbles left, user bubbles right, time on every message, immediate replies, typed input plus clickable numeric options. Minimize (keeps the conversation), close (saves it to the history when the user interacted; next open starts blank), resize (with min/max), full screen on phones without horizontal scroll.
- Left panel with past chats, newest first, with DD-MM-AAAA HH:mm and a short title; a past chat opens read-only with a banner, input disabled, and buttons to return to the active chat or start a new one. Collapsible on narrow widths.
- Requirement change (during implementation): the chat history must be persisted **per account on the server**, so it is visible in a new session, browser or device.
- Modular code (tree data, pure engine, history client, window UI), tests for tree integrity, engine and history, release bookkeeping.

## Decisions
- D1: Modules. `public/js/help/helpTree.js` holds pure data (`HelpTree.list` / `HelpTree.nodes`: menus `{ id, title, text, options: [{ label, next }] }`, leaves `{ id, title, steps, tip }`). `public/js/help/helpEngine.js` is a pure engine (`HelpEngine.create(tree)` → `start`, `choose`, `current`, `path`, `title`, `labelFor`). `public/js/help/helpHistory.js` is the async history client. `public/js/components/helpAssistant.js` is the window (built with `create`/`on`, never `innerHTML`). The three help modules export through `module.exports` when present, so Jest requires them directly; the window is tested with `tests/helpers/fake-dom.js`.
- D2: Tree. 8 level-1 topics mirroring the real sections (Transacciones; Cuentas, saldos y transferencias; Bienes; Alquileres, inquilinos y cobros; Obligaciones, vencimientos y pagos; Avisos; Configuración; Perfil, Logs, deshacer y acceso), 216 nodes, 174 leaves. Labels were taken from the page/component code (`pages/*.js`, `components/*.js`, `utils/wealth-records.js`) where they differ from the functional document (e.g. "Histórico de alquileres", "Agregar obligación", "Cargar documento", "Añadir nota"). Copy uses voseo like the rest of the app. Goals (`summary.js`) have no screen and are not described. A node may point to a node of another branch (shared answers); "back" follows the visited path.
- D3: Numbering. Options are 1–8 (a menu never has more than 8); **9** (or "atrás"/"volver") = previous step, **0** (or "menú"/"inicio") = main menu, listed under every node except the main menu itself. Input is trimmed, accent/case-insensitive and accepts "2.", "2)" and "02". Invalid input keeps the node and repeats its options with the valid numbers.
- D4: Window. Non-modal `role="dialog"` with `aria-label`, `role="log"` live region (silenced while re-rendering a whole conversation), focus to the input on open/restore. **Escape minimizes** (never discards anything). Only the latest bot message's chips are enabled. z-index 170: above dialogs (150) and below toasts (200), so the help stays readable while a dialog is open. The "Ayuda" navbar button has `data-action="help"` (no `data-route`, so the router never highlights it). Logging out (navigating to the login screen) closes the window, saving the chat.
- D5: Resize. A handle on the top-left corner (the window is anchored bottom-right) changes width and height with pointer events or the arrow keys, clamped to 320 × 360 px and the viewport minus 32 px; stored per browser in `localStorage` (`pate_help_size`, try/catch). At ≤ 640 px the window is full screen and the handle is hidden. The history panel is a column when the window is ≥ 620 px wide (open by default) and an overlay toggled by "Historial" otherwise.
- D6: Storage (revised). Chats are stored on the server per account: `GET /api/help-chats` (newest first by `startedAt`), `POST /api/help-chats` (`{ startedAt, endedAt, title, messages: [{ from: 'bot' | 'user', text, at }] }`), `DELETE /api/help-chats/:id`, in the per-user JSON collection `help_chats` (`src/routes/help-chats.js`, behind `requireAuth`). Validation: ISO timestamps, end not before start, 1–500 messages, text ≤ 4000 characters, at least one user message, unknown fields dropped, title ≤ 120 (default "Conversación"); at most 100 chats per account, the oldest dropped. The route has its own 2 MB JSON parser (the global one keeps 100 kB). Help chats are skipped by the activity log (`SKIPPED` in `src/services/activity-log.js`). Bot messages are flattened to text (one line per step/option) when saved, so a past chat renders as plain read-only text.
- D7: Offline. `HelpHistory` keeps an in-memory cache per user. A failed save (network/5xx/401) moves the chat into a retry buffer (memory + `localStorage` `pate_help_pending_<userId>`, max 20, try/catch) that is shown as "Pendiente de guardar" and flushed on the next open; on `pagehide` the active chat goes to that buffer. A 400/413 rejection is dropped (it would never be accepted). A failed history load only shows a soft notice in the panel; the chat keeps working.
- D8: Version 1.22.0, service worker cache v57 (help scripts added to `STATIC_ASSETS`, loaded before `router.js`/`app.js`), functional document section 13.3.
