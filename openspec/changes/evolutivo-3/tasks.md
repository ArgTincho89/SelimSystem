# Tasks: Evolutivo 3

Conventions: `strict_tdd: false`, but every task ships its tests in the same commit (Jest + Supertest under `tests/routes`, `tests/services`, `tests/ui`). Prefer NEW test files (the temp db is shared per file). Names, endpoints, fields and collections follow `design.md` (authoritative; spec drift is noted at the top of each spec). `npm test` must pass before each slice is committed; `npm run test:coverage` (global 60%, per-file thresholds in `jest.config.js`) and `npm run test:e2e` run in the final task. All new API fields are optional, so existing suites stay green. Each slice leaves master deployable. Delivery: auto-chain on ONE feature branch `feat/evolutivo-3`; slices are committed sequentially (conventional commits, no AI attribution), then the branch is fast-forwarded to `master` at the end. `public/sw.js` `CACHE_NAME` goes to `selimsystem-v32` in S1 and increments once per UI slice (v32 to v37; S4a has no UI so no bump). Existing `tests/ui/evolutivo*-s*` contract tests that read frontend sources must be updated in the slice that changes those sources.
